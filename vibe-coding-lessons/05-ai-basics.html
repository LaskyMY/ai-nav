AI 黑话扫盲：美术和游戏制作常用词

小K 最近想用 AI 做游戏概念图、角色参考、UI 图标和场景气氛图，结果到处都是"Prompt""Seed""LoRA""ControlNet""RAG""Agent"这些黑话。G 哥说：别慌，这节不是讲论文，而是把美术和游戏制作里最常遇到的 AI 术语讲成人话。

📚 课程目录
SCENE · 午饭时间

小K："G哥，我昨天看技术文章，一句话里出现了五个我不认识的词。 最气的是作者完全不解释——好像默认全世界都该知道什么是 Token、什么是 Agent。"

G 哥："哈哈，行业黑话就是这样——创造门槛的人，自己进了门就忘了门外还有多少人。 这样，我用你今天中午点外卖这件事，帮你把这些词全部串一遍。"

为什么要懂这些概念

不懂黑话 = 被关在 AI 工具的大门外面。懂了这些 = 你就知道怎么"使唤"AI 了。

2025 年了，一个程序员如果不了解 AI 工具的基本概念，跟 2005 年不会用搜索引擎的程序员是一样的处境—— 不是能力不行，是信息获取效率差了几十倍。你今天不用成为 AI 专家，但至少要能听懂别人在说什么。

概念图：文生图、参考图、风格、Seed角色资产：LoRA、一致性、ControlNet、局部重绘游戏制作：Agent、MCP、RAG、批量脚本

第一站：LLM —— 那个"读了半个人类文明"的超级读者

LLM = Large Language Model = 大语言模型。拆开看：

  • 大（Large）：不是一般的大。GPT-4 的参数数量没公开，但业界估计在 1.76 万亿左右。 什么概念？把它类比成一个人读过的书——它几乎读完了互联网上所有公开的文本。
  • 语言（Language）：它专门处理文字。能读、能写、能翻译、能摘要、能推理。
  • 模型（Model）：它是一个数学结构——说白了就是一个超级复杂的公式，输入文字 → 算出最可能的下一个字 → 输出。
🍜 外卖比喻

LLM 就像一个读了全城所有菜谱和美食评论的超级吃货。 你跟他说"我想吃辣的"，他能告诉你川菜湘菜的区别、推荐最近的店、甚至帮你估算配送时间。 但他不会做饭——他只会告诉你关于饭的一切，但没有手去拿锅铲。

常见的 LLM 名字你大概听过：Claude（Anthropic 出品）、GPT-4（OpenAI 出品）、Gemini（Google 出品）、DeepSeek（深度求索出品）、通义千问（阿里出品）。它们本质上都是同一类东西——超大文本预测引擎。

第二站：Token —— AI 的"最小阅读单位"

LLM 不是按"字"读的，是按 Token 读的。一个 Token 大概等于：

  • 一个常见中文字 ≈ 2 个 Token
  • 一个英文单词 ≈ 1-2 个 Token
  • "Claude Code" ≈ 3 个 Token（"Cl" "aude" " Code"，英文按词根切分）
🔑 为什么 Token 概念很重要？

因为 LLM 有一个上下文窗口（Context Window）——它能"同时看到"的 Token 数量是有限的。 比如 Claude 的上下文窗口是 200K Token，大概相当于一本 300 页小说的量。 你发过去的对话历史 + 项目代码 + 你的问题，全部加起来不能超过这个上限。 超过了，它就会"忘记"最开头的内容。

第三站：Prompt —— 你跟 AI 说话的方式

Prompt 就是你对 AI 说的话。但"问得好"和"问得随便"，AI 给你的回答质量是天差地别的。

👎 烂 Prompt "帮我写个函数。"

没说语言、没说功能、没说输入输出。
AI 只能猜——猜错是大概率事件。
👍 好 Prompt "用 TypeScript 写一个函数：输入一个 TodoItem 数组，返回按紧急程度排序后的数组——红色排最前，黄色中间，绿色最后。"

AI 不需要猜，直接干活。

Prompt 的核心不是"打字"——是"给上下文"。你说得越具体，AI 做得越准。 后面 §6 和 §7 讲 Claude Code 和 Codex 的时候，你会反复看到这个原则。

第四站：Agent —— 从"问一句答一句"到"自己干活"

Agent = 智能体。这个东西是 2025 年 AI 圈最热的词。

普通 LLM 的用法：你问 → 它答。结束了。你再问 → 它再答。像跟一个图书管理员对话。

Agent 的用法：你给一个目标 → 它自己拆成步骤 → 自己一步步执行 → 遇到问题自己想办法 → 做完了告诉你结果。 像你请了一个助理。

🔧 外卖比喻（续）

LLM = 告诉你"附近有什么好吃的"的吃货。
Agent = 一个真的帮你把外卖点好的助理—— 他知道你的地址、你的口味、你的预算，自己打开外卖 App、搜索、比价、下单、等配送。
你只需要说"帮我在 12 点前搞定午饭"，他全包了。

Claude Code 和 Codex 本质上都是 Agent——它们不是"你问它答"的聊天机器人， 而是能读你的整个项目、跑命令、改文件、提交代码的编程助手。 这也是它们和网页版 ChatGPT/Claude 最本质的区别。

第五站：MCP —— AI 的"万能遥控器协议"

MCP = Model Context Protocol = 模型上下文协议。名字看着吓人，拆开就好懂了：

  • Model（模型）：指的是 LLM，即 AI 本身。
  • Context（上下文）：AI 需要从外部获取的信息——你的文件、你的数据库、你用的 API 等等。
  • Protocol（协议）：一种"约定好的说话方式"。就像 HTTP 是浏览器和服务器之间约定好的说话方式一样。

所以 MCP 翻译成人话就是："让 AI 能跟各种外部工具说话的一套标准接口"。

没有 MCP 的时代：每接一个新工具（文件系统、数据库、API），AI 都要专门写一套连接代码。 有了 MCP 之后：AI 只需要说"给我读这个文件"，不管文件在哪、底层是什么存储——MCP 帮你翻译。 就像 USB 出来之前，键盘、鼠标、打印机各有各的接口，USB 把它们统一了。

第六站：RAG —— 让 AI 查资料再回答

RAG = Retrieval-Augmented Generation = 检索增强生成。这个缩写太吓人了，拆开：

  • Retrieval（检索）：先去找相关资料
  • Augmented（增强）：把找到的资料塞给 AI
  • Generation（生成）：AI 根据你给的资料 + 它自己的知识，生成答案
📖 考试比喻

开卷考试 vs 闭卷考试：
不用 RAG = 闭卷考试——AI 只能靠记忆回答，可能记错。
用了 RAG = 开卷考试——先翻书找到相关章节，再回答。答得更准、能溯源。
Claude Code 读你的项目代码来回答问题，其实就是一种 RAG——它"检索"了你的项目文件，"增强"了自己的知识库，"生成"了针对你的项目的回答。

第七站：文生图 / 图生图 / 多模态 —— 美术小白最先遇到的三件事

如果你不是程序员，而是想做角色、场景、道具、UI、分镜，那你最先遇到的不是代码，而是这三个词：

文生图（Text to Image）

你用文字描述画面，例如“赛博朋克风格的药剂商店，夜晚，霓虹灯，俯视角”。适合做第一轮概念发散。

图生图（Image to Image）

你先给一张草图、截图或参考图，再让 AI 按它改。适合把线稿、白模截图、UE 截图变成气氛图。

多模态（Multimodal）

AI 不只看文字，也能看图、看视频、听声音。你可以丢一张 UI 截图，让它指出层级和可读性问题。

Reference / 参考图

给 AI “这张图的构图、这张图的材质、这张图的色调”。对美术来说，参考图就是你的视觉 brief。

美术工作流里的真实用法

先用文生图快速出 20 张方向图，再挑 2 张做图生图细化，最后把角色、材质、UI、场景分别交给不同工具继续打磨。这个过程不是“AI 替你画完”，而是“AI 帮你更快找到方向”。

第八站：Seed / Checkpoint / LoRA —— 为什么同一个提示词画出来不一样

很多新人第一次用绘图 AI 会崩溃：明明 Prompt 一样，为什么每次图都变？这里就要认识三个图像圈黑话。

黑话大白话游戏制作里怎么用
Seed随机种子。它决定这次生成从哪一个随机起点出发。想保留构图大方向，只改衣服、颜色、光照时，先固定 Seed。
Checkpoint / Model底模。它决定 AI 的整体画风和能力边界。写实角色、二次元角色、像素风 UI、建筑概念图，通常会选不同底模。
LoRA小型风格/角色补丁。像给底模临时装一个技能包。让同一个角色在立绘、表情、半身像里保持更一致；也能套特定美术风格。
VAE影响颜色、细节还原和画面解码的组件。图发灰、颜色脏、细节糊时，有时不是 Prompt 问题，而是 VAE 或模型搭配问题。
有意思的转折

新手常以为“我 Prompt 写得不好”。但在绘图 AI 里，Prompt 只是方向盘；Seed、Checkpoint、LoRA 才是车、路和发动机。

第九站：ControlNet / Pose / Depth / Canny —— 让 AI 听构图，而不是自由发挥

如果你做游戏美术，会很快发现一个问题：AI 很会画“好看的图”，但不一定画“你要的图”。ControlNet 这类工具，就是用来给 AI 加结构约束。

Pose / 姿势控制

给角色骨架或动作参考，让 AI 按指定姿势画。适合做角色站姿、攻击动作、宣传图姿态。

Depth / 深度图

告诉 AI 哪里近哪里远。适合把 3D 白模截图变成场景气氛图，同时保留空间关系。

Canny / 线稿边缘

提取线条轮廓，让 AI 按轮廓出图。适合 UI 图标、道具剪影、建筑外形。

Inpaint / 局部重绘

圈出不满意的地方只改那里。比如脸崩了、手错了、按钮文字乱了，不用整张重来。

这类工具对游戏制作特别重要，因为游戏资产经常不是“随便好看就行”，而是要符合已有角色设定、镜头构图、UI 尺寸、引擎截图和策划需求。

第十站：Embedding / Vector DB / RAG —— 让 AI 记住你的项目设定

做游戏最怕 AI 胡编设定：角色名字写错，世界观前后矛盾，技能名乱变，UI 文案不统一。这时就会遇到 Embedding、向量库、RAG。

没有 RAG你问：“这个 NPC 应该怎么说话？”
AI 靠记忆和猜测回答，可能把冷峻刺客写成阳光少年。
有 RAG先把角色设定、剧情大纲、术语表、关卡文档塞进资料库。AI 回答前先查资料，再按项目设定写。
黑话大白话美术/游戏场景
Embedding把文字、图片变成一串数字坐标，方便 AI 判断“像不像”。搜索相似参考图、找相似剧情段落、匹配角色设定。
Vector DB / 向量库专门存这些坐标的资料库。把美术规范、世界观、UI 文案、道具清单做成可检索知识库。
RAG先检索资料，再让 AI 生成答案。让 AI 写任务描述、NPC 台词、图标命名时遵守项目设定。
Grounding让回答落在给定资料上，不许瞎编。要求 AI “只根据这份角色设定回答，不知道就说不知道”。

第十一站：Tool Calling / Function Calling / Agent —— AI 不只是聊天，还能干活

对游戏制作小白来说，Agent 最有用的地方不是“自动做完整游戏”，而是替你执行一串重复动作。

Tool Calling

AI 调用外部工具。比如让它读取文件、截图、跑脚本、查表、生成缩略图。

Function Calling

更结构化的工具调用：AI 不是随口说，而是按固定参数调用一个函数。

Agent

能自己拆步骤、调用工具、检查结果的 AI 助理。Claude Code、Codex 就属于这类。

MCP

让 Agent 接各种工具的统一协议。以后接引擎、表格、素材库、版本库都靠这类思路。

真实例子：你可以让 Codex 扫描一批 UI 图标文件名，找出命名不统一的；让它生成一份图标清单；让它检查课程网页有没有坏链接；让它把美术规范整理成可读文档。这些都比“帮我做个游戏”更实际。

第十二站：Markdown / 表格 / 代码块 —— AI 最常用的交付格式

你跟 AI 聊久了会发现，它特别喜欢用 Markdown。这不是某种编程语言，而是一种很轻量的排版格式：既能让人读得舒服，也方便 AI 输出结构化内容。

Markdown 写法看起来是什么美术/游戏制作里怎么用
# 标题一级标题写美术规范、角色设定、任务说明时分章节。
- 清单项目符号列表列参考图要求、导出规格、检查项、改图意见。
| 表格 |表格整理资产清单、角色表、UI 图标状态、Prompt 版本对比。
```代码块```保留格式的文本块放 Prompt 模板、JSON 配置、CSV、命令行、脚本片段。
> 引用引用块标出策划原文、用户反馈、审查意见，不和 AI 的建议混在一起。
# 角色概念图 Brief - 目标：给一名冰系女法师做 6 张方向图 - 风格：半写实，偏暗黑奇幻 - 必须保留：蓝白配色、长杖、肩部晶体结构 - 不要出现：现代服装、枪械、过度暴露 - 输出格式：每张图给一句 Prompt + 适合的参考关键词
有意思的转折

Markdown 是 AI 协作的“通用稿纸”。你会 Markdown，不是为了炫技，而是能让 AI 把脑暴、需求、表格、测试、复盘都交付成别人能直接读的形状。

第十三站：Skill / System Prompt / Rules —— 把一次好经验变成固定工作方式

如果你每次都要跟 AI 说一遍“请按 UI/UX 标准审查”“请用中文回答”“不要乱改文件”“输出表格”，那就太累了。于是 AI 工具里会出现一些固定行为规则。

System Prompt

系统级指令。它比普通聊天更底层，决定 AI 的角色、边界和默认行为。比如“你是一个代码助手，优先读项目文件”。

Skill

一包可复用的专业说明书。比如 UI UX Pro Max 告诉 AI 怎样审查界面，imagegen 告诉 AI 怎样生成图片。

Rules / AGENTS.md

项目规则文件。告诉 AI 这个项目怎么沟通、怎么改文件、哪些命令不能乱跑、文档用什么格式。

Memory

长期记忆。记录你偏好的表达方式、项目习惯、曾经确认过的结论，避免每次从零解释。

对美术和游戏制作来说，Skill 可以非常实用：比如“角色设定审查 Skill”“UI 图标导出检查 Skill”“UE 材质命名规范 Skill”“课程排版审查 Skill”。它们不是让 AI 变聪明，而是让 AI 稳定地按同一套标准工作。

你想固定什么适合放哪里例子
整个 AI 的默认身份和边界System Prompt默认中文沟通；回答前先读上下文；不确定就说明。
某一类专业任务的流程SkillUI 审查、图像生成、角色设定检查、冒烟测试。
当前项目的本地规矩Rules / AGENTS.md文件编码、目录结构、P4 要求、不要跑构建命令。
跨会话都要记住的偏好Memory用户喜欢图文并茂、喜欢聚类，不喜欢流水账。

第十四站：Artifact / Canvas / Diff / Patch —— AI 交付内容时常见的界面黑话

不同 AI 工具会把结果放在不同地方，名字也不一样。你不需要背产品名，但要知道它们在工作流里代表什么。

Artifact / Canvas

AI 单独开出来的一块作品区。适合放文档、网页、图表、课程讲义，不要混在聊天记录里。

Diff

修改前后的差异。代码、文档、网页都能看 diff，方便你确认 AI 到底改了哪里。

Patch

一包可应用的改动。像“把这些修改打成补丁”，适合工程协作和审查。

Checkpoint

这里不是绘图模型，而是工作进度存档点。复杂任务里要经常停下来确认方向。

真实例子：你让 AI 修改课程网页，它不应该只说“我优化了”。更专业的交付是：列出修改摘要、给出 diff、说明验证方式、截图确认效果、留下下一步风险。

第十五站：Hallucination / Eval / Guardrail —— 为什么不能全信 AI

黑话听起来越高级，越要记住：AI 会错，而且会错得很自信。

黑话什么意思小白怎么防
Hallucination / 幻觉AI 编出不存在的事实、API、素材规范或引擎功能。让它给出处、给文件路径、给验证步骤；不确定就说不确定。
Eval / 评测用固定题目或测试检查 AI 输出质量。比如固定检查：图标是否透明背景、命名是否统一、课程链接是否可打开。
Guardrail / 护栏限制 AI 不要越界。告诉 AI：不要改原画设定，不要新增玩法，不要编不存在的引擎接口。
Human in the Loop人仍然在关键节点审核。AI 出 20 个方向，人来定审美、角色性格、商业取舍。

第十六站：Context Engineering —— 比 Prompt 更重要的“喂资料能力”

现在很多人不再只说 Prompt Engineering，而是说 Context Engineering。意思是：你不只是写一句提示词，而是在设计 AI 能看到什么资料、按什么顺序看、哪些必须遵守、哪些只是参考。

给美术和游戏制作小白的模板

以后你问 AI 时，可以按这个顺序喂资料：目标是什么、受众是谁、参考图/设定有哪些、不能做什么、输出格式是什么、验收标准是什么。你会发现 AI 立刻从“乱聊”变成“像助理一样工作”。

第十七站：Fine-tuning vs Prompt Engineering —— 两种"教 AI"的方式

如果你想教 AI 做一件它不擅长的事，有两种方式：

📝 Prompt Engineering（写提示词） 不需要修改模型本身。
你只是把话说得更清楚。
成本低、见效快、谁都能干。
缺点：复杂规律靠提示词教不会。
🔧 Fine-tuning（微调） 拿一堆你自己的数据，"训练"模型。
相当于你给模型补了一堂课。
成本高、需要标注数据。
优点：能教模型掌握特定领域的规律。

对 99% 的新人来说，先练好 Prompt Engineering。 微调是有了明确场景和数据之后才考虑的事——跟你现在没关系。
