程序是怎么跑起来的

小K 写好的"纸条"电脑根本不认识。从"一行行字"到"双击能跑的程序"，中间发生了什么？

📚 课程目录
SCENE 1 · 第二天上午

小K： "G哥，我把昨天那段代码抄了一份保存成 hello.cpp，结果双击没反应啊。"

G 哥（笑出声）： "你以为代码是 Word 文档？双击就能跑？那中间还得有人翻译给电脑听。"

小K： "翻译？谁来翻译？"

G 哥： "一个叫编译器的程序。你写出来的是人话，CPU 要听的是 0 和 1。 编译器就是你雇的那个翻译官。今天上午你什么都不干，就盯着看——从你写的那几行字，到真能跑的程序，中间到底发生了啥。"

为什么要懂这个

"编译"这个词你以后每天都会听到 100 遍。如果不知道它到底在干嘛， 你和团队的每一句沟通都会卡顿一下。

UE 大项目全量编译要 30 分钟+。 UE 程序员对"编译时间"的执念，几乎是行业心智之一。 今天搞清楚为什么这个动作存在，后面所有"为什么这么慢"、 "增量编译"、"模块"、"链接错误"才有得聊。

更重要的是：后面几天你会开始真正改代码。每次改完， 你都要等编译。如果不知道编译在干什么，等待就是"焦虑"。 知道了，等待就是"OK，它在做翻译，差不多了"。

昨天我们说过：CPU 只懂 0/1，所以人写代码，要有一个"翻译"过程把它转成机器指令。 这个翻译过程就叫编译。今天我们把这条流水线从头到尾走一遍。

从源码到程序：四个阶段

① 源代码：你写的那张纸条

.cpp、.py、.cs 这些都只是普通文本文件， 和 .txt 没本质区别。 你用记事本就能打开它、改它，操作系统不会觉得它"特别"。

它特别的地方是内容——里面写的字符串遵循 C++ 的语法规则。仅此而已。

② 编译：把"人话"翻译成"机器指令"

编译器（compiler）本身是一个程序——一个专门做"翻译"的程序。 你给它一份 hello.cpp，它逐行"读"完之后， 生成一份 hello.obj（Windows 上）或 hello.o（Mac/Linux）。

这个 .obj 里面装的不是文字了，是机器码——一串十六进制数字：

48 89 5C 24 08 57 48 83 EC 20 48 8B D9 48 8B 49
08 E8 9F 21 00 00 90 48 8B 4B 10 ...

每两个字符是一个字节，每个字节都是 CPU 能直接读懂的指令。 人完全看不懂，但 CPU 看一眼就知道该干嘛。

为什么要懂这个

编译器不是"一个"，是好几个——UE 在不同平台上用的是不同的编译器。

Windows 上 UE 用的是 MSVC（Microsoft Visual C++，Visual Studio 自带的编译器）。 Mac 和 Linux 上用的是 Clang。 同一个 .cpp 文件，用 MSVC 和 Clang 分别编译，都会得到机器码， 但中间过程可能不一样，有时候报的错也不一样。 这就是为什么有些代码在 Windows 上能编译，在 Mac 上不行——不是代码的问题，是编译器的问题。

③ 链接：把碎片拼成一个完整程序

现在假设你写了三个 .cpp 文件：main.cpp、utils.cpp、tool.cpp。 编译完之后你得到三个 .obj 文件。每个都是独立的机器码碎片。

但 main.cpp 里调了 utils.cpp 里写的函数 DoSomething()。 编译 main.cpp 的时候，编译器看到 "DoSomething" 这个调用， 但它不知道这个函数在哪里——它只是一个"名字引用"， 需要后面有个人来把这个名字填成一个真正的内存地址。

链接器（linker）就是填地址的人。它把所有 .obj 文件扫一遍， 把每一个"我在这里引用了一个外部的东西"的地方都找到，然后把地址都填好。 拼完之后输出一个最终产物：可执行文件（Windows 上是 .exe）。

编译（Compile） 每一章手稿独立翻译成同一种语言。 翻译官不认识别的内容，只翻译眼前这一章。
链接（Link） 把翻译好的章节装订成一本完整的书， 并且把"请参见第三章第7页"这种交叉引用全部填上正确的页码。
⚠️ 新人最早遇到的一类错误就是"链接错误"

编译错误：你语法写错了，编译器看不懂。比如少了个分号、拼错了一个词。

链接错误：你语法都对，每一章都能独立翻译完，但装订的时候发现——"你说第三章有个第7页，我把整本书翻遍了，根本没这一页！"

UE 里最常见的链接错误是 LNK2019: unresolved external symbol—— 你调了一个函数，但它不存在，或者它所在的 .cpp 没有被一起编译进来。Day 7 会展开讲。

④ 运行：CPU 真的在执行了

你双击 hello.exe，操作系统把它从硬盘加载到内存， 然后告诉 CPU："从这个地址开始一条条往下读。" CPU 就开始执行那一串机器码—— 这才叫程序"跑起来"了。

编译型 vs 解释型：编程世界的两条路

为什么要懂这个

这个区别决定了你为什么要等 30 分钟编译，决定了 Python 为什么可以"边跑边写都行"。 它也是 UE 选 C++、不选 Python 做核心引擎的根本原因。

理解了编译型和解释型的区别，你就理解了整个编程世界最基本的分类。 以后别人跟你说"这门语言是编译型 / 解释型 / JIT"，你脑子里立刻有一张结构图。

上面那一套（编译→链接→运行）是 C++ 的玩法，叫编译型语言。 先把所有代码整本翻译成机器码，再交给 CPU 跑。 优点是跑起来极快，因为 CPU 直接执行机器码，没有任何中间人。 缺点是改一行代码就得重新翻译整章甚至整本。

UE 的全量编译可能要 30 分钟到 1 小时，就是这个原因—— UE 引擎+项目+插件加起来可能有几百万行 C++，全翻译一遍就是这么久。

另一种玩法叫解释型语言，代表是 Python。 你写 hello.py，不需要编译这一步， 直接跑 python hello.py。 Python 解释器边读你的代码边翻译边执行——读一句，翻一句，跑一句。

优点：改了就能跑，不用等编译。缺点：跑起来比编译型慢几十到几百倍， 因为每次执行都要经过"解释器"这个中间人。

🔑 一个能记一辈子的画面

编译型（C++）——把整本英文小说提前翻译成中文再交给读者。 翻译要很久，但读者拿到中文版读得飞快。

解释型（Python）——找一个同声传译，读者每听一句， 传译实时翻译一句。开始得很爽，但每句都要等翻译，整体慢。

那为什么 UE 选了 C++ 这条路？ 因为游戏要跑 60 FPS——每帧只有 16 毫秒。 多一两毫秒就掉帧了。C++ 的"翻译完猛跑"正好适合这个场景。

Python 在 UE 里的角色不是"跑游戏"，而是"跑开发工具"—— 批量改几百个资产的命名、自动生成代码、跑流水线脚本。 这些活不需要 1 毫秒的极致性能，但需要"赶紧写完赶紧跑"的速度。 所以 UE 编辑器内置了 Python 支持，让工具开发可以不用每次都等 C++ 编译。

那蓝图（Blueprint）属于哪一种？

为什么要懂这个

蓝图是美术/策划接触 UE 的第一站。搞清它到底在"编译型 vs 解释型"光谱上哪里， 你就能理解为什么蓝图方便、但性能不极致。

蓝图是 UE 自己的体系。你在编辑器里连那些线、连那些节点， 按"编译蓝图"按钮的时候，UE 把这些连线翻译成一种内部格式（叫"字节码"）。 运行时由一个 UE 内置的"虚拟机"逐条执行这些字节码。

打个比方：

  • C++：你写英文，翻译成一本书（机器码），读者（CPU）直接读。最快。
  • 蓝图：你画思维导图，UE 把它翻译成"内部速记符号"（字节码）， 再由一个专门的"速记解读员"（UE 虚拟机）读出来。比直接读书慢，但比完全不懂的人现场翻译快。
  • Python：你写英文，一个翻译官现场一句句翻。最慢。

所以 UE 项目里典型的分工是：

  • 核心战斗逻辑、渲染—— C++（追求极致性能）
  • 编辑器工具、自动化脚本—— Python（追求开发速度）
  • UI 交互、简单 gameplay、策划配置—— 蓝图（不用写代码）

动动手：看一次真实的编译

你现在不需要装任何东西。我们做一个更小的"脑内实验"：

假设你有一个 hello.cpp，里面就一行打印—— 你打开 Visual Studio 的"开发者命令提示符"， 输入一行命令：

cl hello.cpp

这一行干什么？cl 就是 MSVC 编译器的名字。 它读 hello.cpp → 编译 → 链接，在当前目录下生成 hello.exe。

然后你在同一个黑框框里敲：

hello.exe

程序跑了。你看到输出。

这就是 UE 编译的最小化版本。你今后在 UE 里点"编译"按钮时， UE 背后做的事本质上和这个一样——只不过不是编译一个文件，是编译几千个。 不是手动敲 cl，而是由一个叫 UBT（Unreal Build Tool） 的程序自动管理整个过程。

UBT 在后面 Day 5 会细讲。现在你只需要知道： UE 编译不是你在 VS 里点"生成"，而是 UBT 替你调 MSVC/Clang 把几千个 .cpp 一个个翻译完再拼起来。

💡 一个能记一辈子的画面

每次你听见办公室里有人说"我在编译"， 脑子里就浮现这张画面：一台电脑在把人写的字符串 翻译成 CPU 能直接吃的二进制指令。 UE 的全量编译要 30 分钟，是因为整个引擎+插件加起来上千万行代码， 全要重新翻译一遍。

而"增量编译"只翻译你改过的那几个文件——这就是为什么平时改一行代码 编译只要几十秒到几分钟。UE 会智能地只翻译变了的部分。

源代码是给人看的，
可执行文件是给 CPU 吃的。
编译就是中间那道翻译。
