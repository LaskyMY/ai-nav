Prompt 模板库：把需求说到 AI 能干活

小K 发现同一句“帮我做一下”，有时候 AI 像开挂，有时候像在瞎猜。差别不在魔法咒语，而在你有没有把任务、上下文、边界和验收标准说清楚。

📚 课程目录
SCENE · 不是咒语，是交接单

小K：“我看网上都说 Prompt 工程很玄，要写角色、写人格、写一堆咒语。我是不是要背模板？”

G 哥：“不用玄学。好的 Prompt 本质是把工作交接清楚：我要什么、已有条件是什么、不能碰什么、做完怎么算过。”

为什么要懂这个

AI 不是读心术。你给它一句模糊愿望，它就只能用平均答案糊你。

Prompt 模板的价值不是让你显得专业，而是让你每次开工前都不漏关键上下文。尤其是 VibeCoding：你不是一次问完，而是和 AI 一轮轮推进项目。

第一步：一个好 Prompt 的六个格子

格子要写什么糟糕写法更好写法
目标这次到底要完成什么帮我优化一下把课程首页的编程基础模块新增一张 Git 课程卡片
上下文项目背景、当前文件、现有风格你看着办保持现有课程卡片样式，不新增框架
约束不能做什么、范围多大随便改只改课程页和 manifest，不动服务器配置
产出希望 AI 给什么结果给我代码先给方案，再改文件，最后列验证结果
验收怎么判断完成看起来对就行链接检查通过，课程总数正确，上一节/下一节无断链
风险让 AI 主动提醒不确定点别问我如果发现旧结构冲突，先说明再处理
Prompt 不是许愿。
它是你给 AI 的任务说明书、边界线和验收单。

第二步：常用模板库

下面这些模板不用原封不动背。你要学的是它们的骨架：先让 AI 理解，再让 AI 动手，最后让 AI 自证。

模板一：需求脑暴

我有一个初步想法：[一句话需求]。 请你先不要写代码，先和我脑暴需求。 请输出： 1. 这个需求可能对应的 3 类用户； 2. 每类用户最核心的使用场景； 3. 最小可行版本 MVP 应该只包含哪些功能； 4. 哪些功能应该先砍掉； 5. 你需要继续问我的 5 个关键问题。

模板二：技术选型

我要做：[项目目标]。 我的约束是：[时间 / 平台 / 技术水平 / 是否要部署 / 是否要桌面端]。 请给我 3 个技术方案。 每个方案说明： 1. 适合什么场景； 2. 优点； 3. 缺点； 4. 新手风险； 5. 你推荐哪一个，以及为什么不推荐另外两个。

模板三：让 AI 先读项目再改

请先阅读当前项目结构，不要马上改代码。 目标：[这次要做的事] 要求： 1. 先列出你认为相关的文件； 2. 说明每个文件为什么相关； 3. 给出最小修改方案； 4. 明确不会修改哪些文件； 5. 等我确认后再开始实现。

模板四：报错排查

这是我的报错：[粘贴完整报错] 我的系统是：[Windows / macOS / Linux] 我使用的终端是：[PowerShell / CMD / Bash] 我当前目录是：[路径] 请你： 1. 用新手能懂的话翻译报错； 2. 判断是代码、依赖、路径、环境变量还是权限问题； 3. 每次只给一个检查命令； 4. 告诉我正常输出应该长什么样； 5. 不要直接让我重装全部工具。

模板五：UI 审查

请从 UI/UX 角度审查这个页面。 目标用户是：[用户类型] 页面目的：[页面要帮助用户完成什么] 请按以下维度给建议： 1. 信息层级； 2. 阅读节奏； 3. 按钮和操作是否明确； 4. 移动端是否容易读； 5. 哪些地方看起来像临时拼出来的； 6. 给出按优先级排序的修改清单。

模板六：验证和复盘

你刚才完成了这个改动：[改动目标]。 请不要只总结“已完成”。 请输出： 1. 修改了哪些文件； 2. 每个文件改了什么； 3. 我应该如何手动验证； 4. 哪些边界情况需要检查； 5. 如果出问题，优先回滚哪些改动。
AI 互动现场：把模糊愿望改成可执行任务
你

帮我把页面做高级一点。

AI

可以，我会加渐变、动画、卡片、阴影……

你

先停。目标是提升阅读体验，不是加装饰。请先指出当前页面的信息层级问题，再给 5 条最小修改建议。

AI

明白。我会优先检查标题层级、段落长度、目录位置、按钮文案和移动端可读性。
