装好你的工具箱

小K 准备开始动手了。但 UE 工具开发的环境比一般程序员还要重—— Visual Studio、UE、Perforce，加起来 200GB 起步。今天把地图画清楚，明天开始装。

📚 课程目录
SCENE 2 · 第三天早上

小K： "G哥，我准备好了。在哪写代码？"

G 哥（递过来一张便签）： "三个东西要装：Visual Studio、UE 源码版、Perforce。顺序对，一下午；顺序错，搞三天。"

小K： "……为什么装个软件都这么复杂？"

G 哥： "因为你不是装一个软件，是装一个工厂。编辑代码的、翻译代码的、存代码的、 查历史的——每个都是一个独立的大家伙，而且它们之间还得互相认识。"

为什么要懂这个

环境搭建是新人最容易卡住的第一关。不是因为难——是因为东西太多、名字太像、 说明书太散。今天把三个核心工具的角色搞清楚，你明天动手装的时候心里就有地图了。

很多新人花三天装环境不是因为笨，是因为每装一个东西遇到一个陌生术语就停下来查， 查到的解释里又有两个陌生术语——然后整条链断掉。

今天我们就做一件事：把每个工具是"谁"、为什么"必须装它"、 它和别的工具是什么关系，先在脑子里搭好架子。

你要装的三样东西，用一句话说清各自是干嘛的

Visual Studio —— 不是"一个软件"，是一整套编译器+编辑器

为什么要懂这个

VS 是 UE Windows 开发绕不开的工具。但很多新人装 VS 的时候只装了编辑器， 没装 C++ 工作负载——于是打开 UE 项目发现编译不了，卡了三天。

Visual Studio 其实是一个集合。你装它的时候，它问你要装哪些"工作负载"。 这个选择非常重要：

  • 必选：使用 C++ 的游戏开发——这个工作负载会把 MSVC 编译器、 Windows SDK、UE 需要的所有底层库一次性装好。
  • 必选：使用 C++ 的桌面开发——给的是标准 C++ 工具链。
  • 不用管：.NET、Python、Node.js 这些工作负载——和 UE 无关。

装完之后，你的电脑上就有了MSVC 编译器——就是昨天说的那个翻译官。 VS 本身是编辑器（给你打字、看代码、调试的界面）， MSVC 是编译器（在背后做翻译）。UE 编译的时候，界面可以不打开 VS， 但 MSVC 必须在。

💡 一个新人常见坑

装 VS 的时候千万别用默认的"最小安装"——只装编辑器不装编译器。 你必须在安装程序的"工作负载"页勾上"使用 C++ 的游戏开发"。 这个勾不打，整个 UE 开发都走不通。

另外，VS 2022 和 VS 2019 都支持 UE，但新项目一般都从最新版开始装。 问 G哥 一句"团队用哪个版本"就行。

Unreal Engine —— 启动器版 vs 源码版

为什么要懂这个

这个选择会影响你后面一切——能不能改引擎代码、编译要多久、 出了问题怎么排查，都取决于你用的是哪种版本。

UE 有两种方式装到你的电脑上：

启动器版（Launcher / 预编译版） 从 Epic Games Launcher 下载，点一下安装。 引擎的 C++ 代码已经提前编译好了，你拿到的是 .dll 和 .exe。

✅ 装得快，开箱即用
❌ 不能改引擎代码
❌ 不能加 Editor Plugin（C++ 插件）
源码版（Source Build） 从 GitHub 或 Perforce 拉取引擎的完整 C++ 源码， 在你的电脑上自己编译一遍。

✅ 可以改引擎任何一行代码
✅ 完全支持 C++ 插件
❌ 全量编译要 30min~1h+

做工具开发，100% 必须用源码版。 因为你要写的 Editor Plugin 是 C++，启动器版不支持编译 C++ 插件。 你入职的时候，团队应该已经准备好了引擎源码——直接从 P4 拉就行。

Perforce —— 代码界的"网盘+时间机器"

为什么要懂这个

Perforce 是 UE 行业事实上的标准版本控制工具。你每天交代码、取同事的更新、 回退改坏的代码，都要用它。搞不清 P4 的基本概念，工作第一天就会卡住。

Perforce 你可以理解成一个带历史记录的共享文件夹：

  • 你把代码文件放上去（叫"提交 / Submit"），团队的每个人都能拿到
  • 你改了某个文件，P4 帮你记住每一次改动——改了什么、谁改的、什么时候改的
  • 改坏了想回去？P4 能回到任何一个历史版本
  • 两个人同时改了同一个文件？P4 会告诉你冲突了，让你手动处理

为什么 UE 项目用 P4 而不是 Git？ 因为 UE 项目里有大量二进制文件（贴图、模型、音频）， 一个文件就是几百 MB。Git 存这些非常吃力，P4 天生就是为大规模二进制资产设计的。 这个在 Day 9 会展开。

现在你只需要知道 P4 四个最基本的概念：

  • Depot（仓库）：服务器上存所有文件的地方。全公司共享一个。
  • Workspace（工作区）：你本地电脑上"映射"下来的文件夹。 你在这个文件夹里改代码，改完提交回 Depot。
  • Checkout（签出）：告诉 P4 "我要改这个文件了"。
  • Submit（提交）：改完了，把你的修改打包发送回 Depot。
⚠️ P4 和普通网盘最大的区别

网盘是你改了文件，它自动同步。P4 是你必须先 Checkout 再改。 如果你没 Checkout 就直接改了文件，P4 会觉得"这个文件是只读的， 你不能改"——然后你的修改就保存不了。

这是新人第一天最容易撞的墙。记一句话：改之前先 Checkout。

整个搭建流程，浓缩成一张"路线图"

为什么第一次编译要那么久？

为什么要懂这个

第一次看到"编译中，剩余时间 45 分钟"的时候，如果你不知道电脑在干嘛， 你会以为它死机了。知道了，你就会去泡杯咖啡。

拉完源码后，你需要跑两个脚本：

  • Setup.bat——下载引擎依赖（一些预编译的第三方库，几个 GB）
  • GenerateProjectFiles.bat——生成 VS 的 .sln 项目文件，让 VS 认识 UE

然后在 VS 里点"生成解决方案"。这时候编译器开始干活了—— 它要把 UE 引擎的所有 .cpp 全翻译一遍。UE 5 引擎有几万个 .cpp 文件， 这就是为什么第一次编译要 30 分钟到 1 小时。

好消息是：这只是一次性的。以后你只改自己插件的代码， 增量编译通常几十秒到几分钟就完了。UE 的编译系统（UBT）会智能地 只重新编译"你改了的那几个文件 + 依赖了它们的那些文件"。

🔑 记两组数字

全量编译 UE 引擎源码：30 分钟 ~ 1 小时+（取决于 CPU 核心数）

增量编译改一个小插件：十几秒 ~ 两三分钟

编译所需磁盘空间（引擎+项目+中间文件）：150GB~250GB

VS 帮你写，MSVC 帮你译，
UE 帮你跑，P4 帮你记。
四个工具，一个工作流。
