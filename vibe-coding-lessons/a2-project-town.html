SCENE 3 · 第四天上午

小K（盯着文件资源管理器，呆滞）： "G哥……这个项目文件夹里有 Engine、Project、Plugins、Source、Content、Config、 Saved、Intermediate、Binaries……我连目录都看不懂。"

G 哥（拉过一张白纸，画了几个圈）： "你把项目想象成一座小镇。每个文件夹是一个街区，每个街区有固定的功能。 你不需要知道每栋房子是谁的，但你要知道——想去买菜去哪条街，想看病去哪条街， 想拆房子千万不能去哪条街。"

为什么要懂这个

文件夹结构是你每天在文件资源管理器里看到的东西。如果不认识它， 你找一个文件要翻 10 分钟；改错了一个地方的代码，编译会莫名其妙地坏掉。

而且，同事跟你沟通时会一直说"在 Source 目录下"、"去 Intermediate 删一下缓存"、 "Config 里改个参数"——这些是团队的日常用语。 你今天花 20 分钟把这套地图记住，今后每一天都在省钱。

小镇地图：九个核心街区

逐个街区走一遍

🏛️ Engine — 市政厅，所有人的底座

这个文件夹里是 UE 引擎本身。渲染器、物理引擎、音频系统、编辑器框架—— 全在这里面。源码版 UE 的话，这下面有几万个 .cpp 文件。

关键规则：做工具开发时，你一般不改 Engine 目录下的东西。 你是在 Plugins 里写自己的代码，调用 Engine 提供的功能。 就像你可以在商业街开一家店，但不能随便去改市政厅的承重墙。

但有些情况下（修引擎 bug、改渲染管线、加底层功能），你会需要改 Engine。 这时候知道它在哪里就行了。Day 4 会讲什么时候改引擎、什么时候写插件。

🏪 Plugins — 商业街，你的工具就住这里

为什么要懂这个

你作为"工具开发"，你写的代码 80% 都住在这个文件夹里。 这是你的主战场。不认识它，就像厨师不认识厨房。

Plugins 是一个插件集合目录。下面每个子文件夹是一个独立的插件。 比如 Plugins/MyTool/ 就是你写的一个工具插件。

一个典型的插件内部长这样：

Plugins/MyTool/
├── MyTool.uplugin          ← 插件的"身份证"
├── Source/                  ← C++ 代码
│   ├── MyTool/              ← 模块文件夹
│   │   ├── MyTool.Build.cs  ← 编译配置
│   │   ├── Public/          ← 头文件 (.h)
│   │   └── Private/         ← 实现文件 (.cpp)
│   └── MyToolEditor/        ← 另一个模块(编辑器专用)
├── Content/                 ← 插件自带的资产
└── Resources/               ← 图标等资源

现在先不用理解每层是干嘛的。你只需要记住：你今后每天打开的这个文件夹，就是 Plugins 下的某个子文件夹。 Day 5 会把这张图彻底拆清楚。

🔧 Source — 工坊区，代码住的地方

这个文件夹只在源码版出现。它里面是引擎的 C++ 源代码。 和 Plugins 类似的结构：下面有 Runtime、Editor、Developer 等子目录， 每个下面又有 .cpp / .h / Build.cs。

你作为工具开发者，更多时候是读 Source 里的代码—— 看引擎提供了什么功能，看别人怎么写的——而不是改它。

📦 Content — 仓库，美术资产的天下

Content 里放的是 UE 的资产文件（.uasset）。贴图、模型、材质、蓝图、 动画、音频统统在这里。这些文件不是文本——你用记事本打开会看到乱码。 它们是 UE 自己的二进制格式。

你写工具时经常会操作 Content 下的资产—— 比如"选中 100 张贴图批量改名"、"扫描所有材质找出参数不对的"。 你的工具就是在操作这个仓库里的东西。

⚙️ Config — 设置面板，改参数不用编译

Config 里是一堆 .ini 文件——纯文本的配置文件。 引擎设置、项目设置、插件设置、输入映射……全是 ini。

为什么 Config 重要？因为改 ini 不需要编译。你加了一个新的配置项到 ini 里， 重启编辑器就生效。很多工具的行为可以通过 ini 来控制，而不需要每次改代码、 等编译。

📝 Saved — 存档，可以随便删

Saved 里是运行时产生的临时数据： 编辑器日志（Logs/）、崩溃报告（Crashes/）、自动保存（Autosaves/）、 配置文件缓存（Config/）。

如果你遇到了奇怪的编辑器问题，"删 Saved 目录"是 UE 程序员的第一反应—— 就像"重启试试"之于普通用户。Saved 删了不会丢任何代码或资产， 下次启动编辑器会自动重建。

🍳 Intermediate — 厨房，编译的中间产物

编译器在翻译你的 .cpp 时，会产生大量中间文件（.obj、预编译头等）。 这些都扔在 Intermediate 里。

如果编译出了奇怪的错误——比如明明改了代码但编译出来还是旧的—— 删掉 Intermediate 然后重新编译，通常能好。 这是 UE 排错三板斧之二（第一是删 Saved，第二是删 Intermediate）。

📤 Binaries — 成品柜，编译的最终产出

编译完的最终产物——.dll（动态链接库）和 .exe（可执行文件）——放在这里。 你双击 UE 编辑器的时候，Windows 加载的就是 Binaries 下的 .exe 和 .dll。

你的插件编译完之后，对应的 .dll 也会出现在这里。 这就是为什么"代码改完 → 编译 → 编辑器里就能用"—— UE 加载了你刚编译出来的新 .dll。

⚠️ 两个绝对不能手动改的文件夹

Intermediate 和 Binaries——这两个文件夹里的东西全是编译自动生成的。 你永远不要手动去修改里面的任何文件。 它们唯一的维护方式就是"删掉然后重新编译"。

如果你手动改了里面一个 .dll 或 .obj，下次编译行为完全不可预测。

新人最常问的三个问题

"我改的代码在哪个文件夹？"

→ Plugins/你的插件名/Source/ 下。具体是 Public/ 下的 .h 和 Private/ 下的 .cpp。 这两个文件夹里面是你每天打开、修改、保存的文件。

"为什么 Content 里看不到我的 C++ 代码？"

→ Content 只放资产（.uasset），不含 C++ 代码（.cpp / .h）。 C++ 代码在 Source 或 Plugins 里。这是两个完全不同的世界， 通过 UCLASS/UFUNCTION 等"魔法词"互相连接。Day 4 展开。

"同事让我去 Config 里改个东西——Config 在哪？"

→ 项目根目录下的 Config/ 文件夹，里面一堆 .ini 文件。 最常用的是 DefaultEngine.ini 和 DefaultGame.ini。 用记事本就能打开。

文件夹结构不是要背的，是要在脑子里画成一张地图。
每次打开项目，你都知道自己站在"镇上哪个位置"。
