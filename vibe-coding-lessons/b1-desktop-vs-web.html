桌面应用 vs 网页：区别在哪

小K 每天用微信、用 UE 编辑器、用 Chrome—— 这三种东西都是"程序"，但它们到底有什么本质区别？为什么有的叫"桌面应用"，有的叫"网页"？

📚 课程目录
SCENE · 某天下班后

小K："G哥，UE 编辑器是桌面应用对吧？那如果我打开 Chrome 访问一个网页版的 UE 编辑器……可能吗？"

G 哥："技术上可能，但体验上差很远。你想想——UE 编辑器为什么是桌面应用而不是网页？ 因为它需要直接读写你硬盘上的文件、调用显卡渲染视口、监听键盘鼠标的精确输入。 十年前这些只能用 C++ 做桌面应用，但现在边界在模糊。"

为什么要懂这个

理解"桌面应用"和"网页"的边界，你才能理解现代开发的技术选型。

我们接下来的实践课要做的是一个桌面应用——不是网页。 如果你分不清这两种东西的技术差异，后面每一步都会感到困惑。 好消息是：今天的 Web 技术已经可以写桌面应用了（Tauri、Electron）， 这意味着你不需要学 C++ 就能写出一个像模像样的桌面程序。

三个维度看区别

🖥️ 桌面应用 安装在操作系统上（Windows/Mac/Linux）。
双击 .exe 打开，有自己独立的窗口。
可以直接读写硬盘文件、调用系统 API。
例：UE 编辑器、微信、VS Code、Photoshop。
🌐 网页应用 跑在浏览器里，不需要安装。
输入网址打开，浏览器管着它的一切。
不能随便读写用户硬盘（出于安全）。
例：B站、知乎、飞书网页版、Google Docs。
🔒 桌面应用的权限 可以读任何文件、开系统托盘、全局快捷键。
可以开机自启、监听系统事件。
可以调用 GPU 做高性能渲染。
权限大 = 责任也大，要注意安全
🔒 网页应用的限制 浏览器把它关在"沙箱"里。
不能随便读文件，不能操作系统设置。
不能创建系统托盘图标。
安全，但能力受限

"混合体"：用 Web 技术写桌面应用

过去十年里最有趣的趋势：你可以用写网页的技术（HTML + CSS + JavaScript/TypeScript）， 写出一个真正的桌面应用。怎么做到的？

核心思路很简单：把一个迷你浏览器嵌入到桌面窗口里。 用户看到的是一个正常的桌面窗口，有标题栏、有任务栏图标、有系统托盘—— 但窗口里面跑的是 Web 页面。同时，框架提供一座"桥"， 让 Web 代码能调用操作系统的原生能力（读写文件、系统托盘、全局快捷键等）。

十年前写桌面应用必须学 C++/C#。
现在你可以用 HTML + CSS + JavaScript 写一个桌面应用，
安装到 Windows/Mac/Linux 上，别人双击就能用。
