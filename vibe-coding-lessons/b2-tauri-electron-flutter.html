SCENE · 周末咖啡馆

小K 打开笔记本电脑，搜索"怎么用 Web 技术写桌面应用"。

第一条结果是 Electron——"用 JS 写桌面应用"。他点进去看了看，又看到有人 在评论区说"Electron 太吃内存了，Tauri 才是未来"。又有人推荐 Flutter……

小K："……所以到底用哪个？"

为什么要懂这个

技术选型是新项目的第一道坎。选错了不是不能改——是改起来成本很高。

你不知道每个选项的优劣，就容易被网上"XXX 是最好的"这类话带着走。 实际上没有最好的框架，只有最适合当前项目的框架。理解各家的 trade-off，你就能自己做判断。

三大主流方案对比

🔑 Electron —— 最成熟，最"重"

原理：每个 Electron 应用都自带一个完整的 Chromium 浏览器（就是你桌面上 Chrome 的核心）。 你的 HTML/CSS/JS 就渲染在这个内置浏览器里。 优点：生态非常成熟——VS Code、Slack、Discord、飞书、Notion 全是 Electron 写的。 社区大、插件多、遇到问题搜得到答案。
缺点：内存占用大（每个应用自带一个浏览器，能不吃内存吗？），安装包大（100MB+ 起步）。
适合：功能复杂、团队大、需要快速迭代的商业产品。

⚡ Tauri —— 轻量级新秀（我们的选择）

原理：Tauri 不打包浏览器。它直接复用操作系统自带的 WebView （Windows 用 WebView2，Mac 用 WKWebView，Linux 用 WebKitGTK）。 底层用 Rust 代替了 Node.js，性能更高、更安全。
优点：安装包极小（可以小到 3MB），内存占用极低。 安全模型更好——默认情况下前端代码无法随意访问系统。
缺点：比较新（v2 2024年才稳定），有些边缘场景的生态还不够丰富。 需要写一些 Rust 代码来做原生操作。
适合：工具型应用、需要小体积和低内存占用的项目。
我们的 FloatThings 就是用 Tauri v2 做的。

🎨 Flutter —— Google 的跨平台方案

原理：Flutter 不用 Web 技术。它用自己的渲染引擎 Skia 画界面， 用一种叫 Dart 的语言写逻辑。界面不经过浏览器，直接画到屏幕上。
优点：界面性能好，跨平台统一（一套代码跑 iOS、Android、Web、桌面）。 组件库丰富，UI 一致性好。
缺点：要学 Dart（小众语言），桌面端支持相对新。 界面上不像"原生"应用（有时看起来怪怪的）。
适合：同时需要移动端和桌面端的项目，重视 UI 一致性的产品。

没有银弹。选型就是选 trade-off。
我们的实践课选 Tauri，因为它恰好解决了"小而美"的需求。
