为什么要懂这个

这一天的目标不是"做一个能用的工具"——是让你体验一次"从零到一"的完整过程。 从新建插件到看到按钮弹窗，每一步都有具体落脚点。跑通这天的内容， 你就有信心了——后面的工具只是在"已经跑通的框架"上叠功能。

我们今天要做什么

做一个最最最简化的 Editor 工具，总共就三样东西：

  • 一个菜单按钮（在 UE 编辑器的工具栏上）
  • 点击按钮后弹出一个对话框窗口
  • 对话框里显示一行文字

就这么多。不操作资产、不改配置、不调复杂 API。 纯粹是为了让你看到——"我在 C++ 里加了几行代码，编辑器里就多了一个按钮"。这个感觉非常重要。

第一步：新建插件，搭好架子

在 UE 编辑器里：Edit → Plugins → 右下角 "New Plugin" → 选 "Editor Toolbar Button" 模板 → 起个名字叫 KFirstTool。

UE 会自动在 Plugins/KFirstTool/ 下生成一堆文件。 生成完了关掉编辑器。

生成的目录结构大概长这样：

Plugins/KFirstTool/
├── KFirstTool.uplugin
└── Source/
    └── KFirstTool/
        ├── KFirstTool.Build.cs
        ├── Private/
        │   └── KFirstTool.cpp          ← 我们要改的文件
        └── Public/
            └── KFirstTool.h             ← 头文件

第二步：看懂自动生成的代码

打开 KFirstTool.h，你会看到类似这样：

#pragma once
#include "CoreMinimal.h"
#include "Framework/Commands/UIAction.h"  // ← UI 操作支持
// ... 几个 include ...

class FKFirstToolModule : public IModuleInterface  // ← 一个"模块类"
{
public:
    virtual void StartupModule() override;   // ← 插件被加载时调用
    virtual void ShutdownModule() override;  // ← 插件被卸载时调用

private:
    void OnToolbarButtonClicked();          // ← 按钮被点击时的"回调函数"
    TSharedPtr<FUICommandInfo> Command;     // ← 命令对象
};

别看花眼——这里面真正重要的就三行：

  • StartupModule()：插件加载时执行——在这里注册你的按钮
  • ShutdownModule()：插件卸载时执行——在这里清理
  • OnToolbarButtonClicked()：按钮被点了——在这里写"弹窗"的逻辑
💡 如果你不太懂上面这些 C++ 类/继承/override

没关系。Day 0 说过——任何代码往上扒都是"变量 + 函数 + 条件 + 循环"的组合。 这里的 class 就是一个"大盒子"，里面装着相关的变量和函数。 virtual void StartupModule() override 就是在说 "这个函数别人已经定义好了名字，我来填具体内容"。

你不需要今天全懂。先把代码跑起来，感觉会帮你理解概念。

第三步：把弹窗代码加进去

打开 KFirstTool.cpp，找到 OnToolbarButtonClicked() 函数。 把它的内容改成：

void FKFirstToolModule::OnToolbarButtonClicked()
{
    // 弹一个系统消息框
    FMessageDialog::Open(
        EAppMsgType::Ok,
        FText::FromString(TEXT("Hello，小K！你的第一个工具跑起来了！"))
    );
}

就这么几行。FMessageDialog::Open 是 UE 提供的一个函数—— 弹出一个系统对话框。第一个参数是"对话框有几个按钮"（Ok = 一个确定按钮）， 第二个参数是"对话框里显示什么文字"。

第四步：确认 Build.cs 里有正确的依赖

打开 KFirstTool.Build.cs，确保 PrivateDependencyModuleNames 里 有 "Slate" 和 "SlateCore"（UI 相关依赖）。 如果弹窗需要的模块不在依赖里，链接器会报 LNK2019。

如果你的依赖列表里有这些，就不用动：

PrivateDependencyModuleNames.AddRange(new string[] {
    "Slate",
    "SlateCore",
    "EditorStyle",
    "UnrealEd",
    // ... 其他
});

第五步：编译 + 跑起来

  1. 右键 .uproject → "Generate Visual Studio project files"
  2. 在 VS 里打开 .sln，按 Ctrl+Shift+B（生成解决方案）
  3. 等编译完成（第一次几分钟，以后几十秒）
  4. 启动 UE 编辑器
  5. 在编辑器工具栏上找到你插件的按钮（可能是一个带插件名的小图标）
  6. 点它
  7. 弹出一个窗口，写着 "Hello，小K！"

如果没看到按钮：去 Edit → Plugins 确认你的插件是 Enabled 状态。 如果编译报错：用 Day 7 的方法，看第一条 error，定位文件和行号。

你做了什么，你什么都没做——但你其实做了很多

为什么要懂这个

你刚刚走的这五步，就是 UE 工具开发的标准流程。今后你做任何工具—— 不管多复杂功能——都是这个流程的放大版。

回顾一下你刚刚做了什么：

你现在可能还不完全懂 FMessageDialog::Open 是什么、 FText::FromString 是什么、为什么参数的类型长那样。 没关系——Day 0 说过，"看代码是把每一行翻译成'它在干嘛'"。 你已经能翻译"哦，这行在弹一个对话框，里面显示一行字"——这就够了。

今后你想在这个工具上叠加新功能，比如弹窗里多一个输入框、 弹窗确认之后批量重命名资产、加一个设置面板……这些都是在 已经跑通的框架上往 OnToolbarButtonClicked() 这个函数里加更多代码。

框架一旦跑通了，后面就是堆功能。而堆功能这件事，AI 特别擅长。

八天前，"代码"在你脑子里没有形状。
八天后，你在 UE 编辑器里点了一下自己写的按钮。
这就是从零到一。
