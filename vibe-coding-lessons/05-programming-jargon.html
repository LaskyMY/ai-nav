编程黑话扫盲：IDE、终端和环境变量

小K：“G哥，别人说‘你在 PowerShell 里看一下 PATH，确认 node 在环境变量里，然后从项目根目录跑 build’。我每个字都认识，但我完全不知道该点哪里。”

G 哥：“这就是编程黑话。它们不是高深概念，但如果没人翻译，新人会卡在最基础的门口。”

为什么要懂这个

很多开发问题不是代码错了，而是“你在哪个工具里、哪个目录下、用哪个命令、带着哪些环境变量”错了。

黑话的价值不是拿来装懂，而是帮你定位问题。你一旦听懂 IDE、终端、Shell、PATH、工作目录、依赖、构建这些词，就能更准确地和同事、AI、报错信息沟通。

第一组：你正在用什么工具

黑话全称/常见说法它到底是什么小白最常误会什么
IDEIntegrated Development Environment集成开发环境。它不只是编辑文字，还能补全、跳转、调试、运行、看项目结构。以为 IDE 只是“高级记事本”。Visual Studio、Rider、WebStorm、VS Code 加插件都可能承担 IDE 的角色。
Editor编辑器更偏向写文本和改文件的工具，例如 VS Code、Sublime。把 Editor 和 IDE 完全等同。编辑器可以很强，但 IDE 通常集成更多项目理解能力。
Terminal终端一个输入命令、查看输出的窗口。它像“和电脑文字对话”的界面。以为终端就是黑框本身。其实终端窗口里还会运行不同 Shell。
Shell命令解释器负责理解你输入的命令。PowerShell、CMD、Bash 都是 Shell。以为所有命令窗口语法都一样。PowerShell 和 CMD 的变量写法、引号规则、管道对象都不一样。
一句话记住

IDE 是你写代码的办公室；终端是你发命令的窗口；Shell 是听懂命令的人。你看到的黑框只是窗口，真正解释命令的是里面运行的 Shell。

第二组：PowerShell、CMD、Git Bash 到底差在哪

Windows 上最容易混乱的就是这几个命令行工具。很多教程复制失败，不是命令错，而是你把 Bash 命令粘进了 PowerShell。

工具常见位置适合做什么注意点
CMDWindows 老命令提示符跑一些传统 Windows 命令、批处理 .bat。语法老，功能少，但很多旧教程还在用。
PowerShellWindows 现代 Shell系统管理、文件操作、脚本、开发命令。现在 Windows 上很常用。变量写法是 $env:PATH，很多 Linux 命令不能原样用。
Git Bash安装 Git 后常见在 Windows 上模拟 Linux/Bash 风格命令。路径、引号、环境变量写法和 PowerShell 不一样。
Terminal AppWindows Terminal它只是承载多个 Shell 的外壳，可以开 PowerShell、CMD、WSL。不要把 Terminal App 和 Shell 混为一谈。
PowerShell 例子
$env:Path
Get-ChildItem
Set-Location D:\www\baoxiaoxing
CMD 例子
echo %PATH%
dir
cd /d D:\www\baoxiaoxing

第三组：路径、工作目录、环境变量

很多“命令找不到”“文件不存在”都和这组词有关。

Path / 路径

文件或文件夹的位置。D:\www\baoxiaoxing 是绝对路径，assets/site.css 是相对路径。

Working Directory / 工作目录

你当前命令所在的文件夹。命令里的相对路径，会从这里开始找。

Environment Variable / 环境变量

系统或程序运行时能读到的一组配置，比如工具安装位置、密钥、运行模式。

PATH

最重要的环境变量之一。它告诉系统：你输入 node、git、python 时，去哪些文件夹里找可执行程序。

最常见的坑

“我安装了”不等于“命令能找到”。你装了 Python，但如果它不在 PATH 里，终端输入 python 仍然可能提示找不到。改完环境变量后，也经常需要重新打开终端。

第四组：运行项目时经常出现的词

黑话什么意思常见例子遇到时怎么问 AI
Runtime运行环境。你的代码需要某个程序来执行。Node.js 跑 JavaScript，Python 跑 .py，JRE 跑 Java。“这个项目需要什么 runtime？版本要求是多少？”
SDK软件开发工具包。Android SDK、Windows SDK、Unreal Engine SDK。“这个报错是不是 SDK 没装或版本不匹配？”
Dependency依赖。项目需要别人写好的包或库才能运行。node_modules、Python 包、NuGet 包。“请先解释这个依赖是做什么的，不要盲目升级。”
Package Manager包管理器。负责下载、安装、锁定依赖。npm、pnpm、pip、NuGet。“这个项目应该用 npm 还是 pnpm？从哪里判断？”
Build构建。把源码处理成可运行/可发布的结果。npm run build、UE 编译、打包桌面程序。“build 失败前最后一个有效错误是什么？”
Dev Server开发服务器。边改边预览的本地服务。localhost:3000、localhost:5173。“这个端口是谁启动的？如何停止或换端口？”

第五组：排查问题时经常出现的词

Log / 日志

程序留下的运行记录。不要只截图最后一行，关键是找到第一条真正的错误。

Error / Warning

Error 通常会阻止继续运行；Warning 是提醒你有风险，但不一定马上崩。

Cache / 缓存

为了加速保留的旧数据。缓存能提升速度，也会让你看到旧页面、旧配置、旧依赖。

Permission / 权限

没有权限写文件、开端口、执行脚本时会报错。Windows 上可能需要管理员权限，Linux 上可能需要 sudo。

第六组：协作时常见的词

黑话人话解释你该注意什么
Repo / Repository代码仓库，项目的版本历史和文件集合。不要随便在不确定的仓库里大改。
Commit一次保存到版本历史里的改动。提交信息要说明改了什么，不要全写“update”。
Branch分支，一条独立的修改路线。做功能前先确认自己在哪个分支。
Merge合并，把一条分支的改动合到另一条。冲突时不要乱点接受全部。
PR / Pull Request请求别人审核并合并你的代码。PR 里要写清目的、改动、验证方式。
Diff / Patch展示“改了哪些行”。让 AI 给 diff，能帮你确认它没有乱改。
AI 互动现场：把黑话翻译成排查步骤
你

终端提示 node 不是内部或外部命令，我是不是代码写错了？

AI

不一定。这个错误通常说明系统找不到 node 命令，可能是 Node.js 没安装，或者 PATH 没配置。

你

请按 Windows PowerShell 给我排查，不要给 Linux 命令。每一步告诉我要看到什么才算正常。

AI

第一步运行 node -v；第二步运行 where.exe node；第三步检查 $env:Path 是否包含 Node 安装目录。改完后重新打开 PowerShell。

以后遇到编程黑话或命令行报错，可以这样问 AI： 请你把下面的报错翻译成新手能懂的话。 我的系统是 Windows，我现在用的是 PowerShell。 请区分：这是代码问题、依赖问题、路径问题、环境变量问题，还是权限问题。 每一步只给一个检查命令，并告诉我正常输出应该长什么样。 不要直接让我重装全部工具。
黑话不是拿来背的。
它的价值是让你听懂一句话：问题到底发生在哪一层。
是代码、工具、路径、环境，还是人的操作流程。
