UI 打磨：用 UI UX Pro 和 Codex 做出产品感

原型能跑只是 60 分。真正让别人“哇”的，是你能把 UI 审查、视觉标准和实现迭代变成一套可复制流程。

📚 课程目录
SCENE · 从能用到想用

小K：“原型功能都通了，但看起来像课程作业。”

G 哥：“这时候不要凭感觉改。让 UI UX Pro 做审查，让 Codex 按审查结果落地。你负责定方向和验收。”

这一节为什么显得高级

UI 打磨不是“换颜色”，而是把审美变成可执行的检查清单。

你用了 UI UX Pro，不是为了说“我用了一个工具”，而是为了让设计判断从主观喜好变成结构化标准：层级、密度、触控目标、颜色对比、状态反馈、响应式。

第一步：先让 UI UX Pro 做审查，而不是直接美化

请以 UI/UX Pro Max 的标准审查这个待办工具原型。 重点看： 1. 信息层级是否清楚； 2. 主要操作是否一眼能找到； 3. 颜色对比和可读性是否达标； 4. 卡片、按钮、输入框的触控目标是否足够； 5. 深色/浅色主题是否风格统一； 6. 动画和状态反馈是否有意义； 7. 移动/小窗口下是否会挤压或溢出。 请输出：问题清单、优先级、修改建议、验收标准。
AI 互动现场：美化不是加氛围感
你

请用 UI UX Pro 的标准审查一下这个原型。

UI UX Pro

主要问题不是颜色不够炫，而是主操作层级弱、卡片密度不稳定、状态反馈不清楚、窄屏阅读压力偏大。

你

把这些审查意见翻译成 Codex 能执行的任务，不要写“更高级一点”这种模糊要求。

AI

可以拆成四条：统一按钮层级；固定卡片间距和状态区；建立语义色 token；为完成、删除、主题切换补明确反馈。

有意思的转折

这一段会让观众意识到：你不是让 AI 随便“美化一下”，而是先让设计审查变成验收标准，再让 Codex 按标准执行。

第二步：把审查结果翻译成 Codex 可执行任务

设计审查如果只是“更高级一点”，AI 很容易乱改。要把审查结果改写成明确任务。

审查发现给 Codex 的任务验收方式
主按钮不突出统一按钮层级：主要操作使用 primary，次要操作使用 outline。第一眼能看出“添加事项”是主操作。
卡片信息密度不稳固定卡片内边距、行高和状态区域，避免内容跳动。多条不同长度事项排列仍然整齐。
主题切换割裂整理设计 token：surface、text、muted、accent、danger、success。深色/浅色都保持品牌感和可读性。
反馈不够明确完成、删除、拖拽、切换主题都要有视觉状态。用户不用猜操作是否生效。

第三步：把“漂亮”拆成四类证据

层级证据

标题、标签、卡片、按钮各有明确权重，用户知道先看哪里、再点哪里。

一致性证据

颜色、圆角、阴影、间距来自同一套 token，而不是每个组件随手写。

交互证据

点击、滑动、拖拽、完成都有状态反馈，动作不是“瞬移”。

可访问性证据

文字对比度、按钮尺寸、键盘焦点、减少动效偏好都被考虑到。

第四步：让 AI 负责实现，但你负责品控

高质量 Vibe Coding 不是“AI 改完我就收”。你要让 Codex 每次改完都报告：改了什么、为什么、怎么验证、还有什么风险。

请根据 UI UX Pro 的审查结果优化界面。 要求： - 不要改变核心业务逻辑； - 优先使用现有组件和 CSS token； - 每次修改后说明：改动点、影响范围、验证方式； - 如果某个建议会增加复杂度，请先提出取舍，不要直接实现。 最后请给我一份 UI 验收清单。
别人看到的是“界面变好看了”。
真正值得学的是：你把审美、工具和工程实现组织成了一条可审查、可复现、可验证的流水线。
